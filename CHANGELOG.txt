--------------------------------------------------------------------------------
ORDER SCREEN  —  UI Overhaul
--------------------------------------------------------------------------------

* Menu item buttons redesigned with Square POS-inspired card style:
  - Solid colored card background (sourced from back-office button color setting)
  - Three-layer soft drop shadow so cards lift off the tray background
  - Food image fills the upper portion of the card, clipped to rounded shape
  - White label band at bottom with item name (bold, word-wrapped) and price
  - Custom SquareGridLayout: tiles are always square, 5-9 columns, 10 px gap
  - CardPosButtonUI suppresses FlatLaf interference with custom paintComponent

* Removed TitledBorder from all order-screen panels (CategoryView, GroupView,
  MenuItemView, TicketView) — replaced with EmptyBorder(2,2,2,2).  Panels no
  longer appear boxed.

* Action button bar (bottom of order screen):
  - All buttons styled consistently via setupActionButton() with icon + label
  - New icon set: btn_kitchen, btn_clockout, btn_orders, btn_driver, etc.
  - Order-type icons added: ordertype_dinein, takeout, delivery, bartab, etc.
  - Pay Total button is wider than other buttons (grows 2x)
  - Pay Total turns amber (0xFFB800) with live total amount when cart is non-empty

--------------------------------------------------------------------------------
ORDER SCREEN  —  Bug Fixes
--------------------------------------------------------------------------------

* FIX: "Pay Total" button was navigating to the Table Selection screen instead
  of the Payment screen.  Root cause: button was wired to doFinishOrder()
  (send-to-kitchen + close) instead of doPayNow() (payment flow).
  Corrected in OrderView.java.

* "Cancel" button renamed to "Cancel Order" for clarity.

* Pay Total button icon changed from pay.png to settle_ticket.png to match
  the consistent btn_* icon style used by all other action buttons.

--------------------------------------------------------------------------------
TRAINING MODE  —  Redesign
--------------------------------------------------------------------------------

* Training mode toggle now requires a full application restart instead of a
  live database hot-swap (which was fragile and could leave Hibernate in an
  inconsistent state).

* New class TrainingMode.java:
  - savePreference(boolean)  — persists the training_mode key to
    floreantpos.config.properties
  - loadAndApply()  — reads the preference and sets the connect string and
    enabled flag before the database is initialised

* Application.initializeSystem() calls TrainingMode.loadAndApply() before
  DatabaseUtil.initialize() so:
    (a) The orange training-mode bar is visible immediately on startup.
    (b) The correct (training or live) database is used from first connection.

* LoginView training-mode checkbox: on toggle, shows a "Restart Required"
  confirmation dialog.  On Yes: saves preference and calls Main.restart().
  On No: reverts checkbox.  Live DB-switch logic removed from doLogin().

* Restaurant.getName() overridden: returns "Training Restaurant" whenever
  training mode is active.  This ensures receipts, kitchen prints, and all
  reports cannot be mistaken for live-data output.

--------------------------------------------------------------------------------
BACK OFFICE  —  Sidebar & Tab Management
--------------------------------------------------------------------------------

* Sidebar extracted into dedicated class BackOfficeSidebarPanel.java:
  - Responsive width (220-300 px, scales with screen width)
  - Collapsible to icon-only mode (56 px) via toggle button
  - Accordion sections with header icons auto-selected by section title
  - Item rows with hover highlight and left-edge accent bar
  - SidebarIcons inner class generates consistent SVG-style icons for each item

* "Enable Multiple Tabs" toggle switch added to the back-office status bar
  (right side, next to restaurant name):
  - OFF (default): clicking any sidebar item closes all open explorer tabs
    first, then opens the selected one — only one tab visible at a time.
  - ON: tabs accumulate side by side as before.
  - Implemented via ToggleSwitchButton (new pill-shaped toggle component).
  - Static flag BackOfficeWindow.multiTabsEnabled wired to the toggle.
  - Sidebar ItemRow uses SwingUtilities.getAncestorOfClass to reliably resolve
    the parent BackOfficeWindow at runtime.

* BackOfficeWindow constructor now sets instance = this so getInstance()
  always returns the live displayed window.

--------------------------------------------------------------------------------
BACK OFFICE  —  Explorer Grids
--------------------------------------------------------------------------------

* CustomCellRenderer: all text/date cells now render with 6 px top/bottom
  padding (EmptyBorder 6,7,6,7).  Row height auto-raised to 34 px if the
  table's current row height is less — applies to all explorers that use
  this renderer (MenuGroupExplorer, MenuCategoryExplorer, MenuItemExplorer,
  ModifierExplorer, MultiplierExplorer, OrderTypeExplorer, PizzaItemExplorer,
  PizzaModifierExplorer).

* PosTableRenderer: same 34 px row-height guard added, covering
  ModifierGroupExplorer, TicketExplorer, and other explorers that use
  PosTableRenderer.

* ExplorerButtonPanel: buttons now carry consistent EmptyBorder(6,16,6,16)
  padding so they are uniformly sized and easy to click.  Default L&F
  rendering is preserved.

* MenuGroupExplorer: "Change Menu Category" extra button created via
  ExplorerButtonPanel.createButton() for size consistency with Add/Edit/Delete.
